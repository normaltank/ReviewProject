## 真正实现的行为

- **输入与证据**：DOCX 已补样式继承检查和纵向合并拒收，无法可靠解析就留错误；CSV 直接读取已核 6×6 业务表单；JSON 有明确契约。冻结原件、原分字符串、分区权限和码点位置不变。历史不安全工作区需重导入，不能绕过新检查。
- **观点与修正**：机器候选不可变，人工路径追加决定；独立观点可拆分、补录、撤销或替换，父子关系和稳定 ID 保留。多处同区证据可跨句连理由、条件和替代。新模型运行另存，不覆盖已有决定；同运行重放幂等，ID 冲突拒收。
- **概念与 A 来源**：实现稳定概念 registry、定义/例子/反例/边界/待确认状态和历史。已整理两个开发候选概念。A 来源导入三条：两条从原生 PPT 逐字核对，一条是既有机器整理；全部保持 candidate、pending_source_review、authority unconfirmed。不是正式 A 标准版本。
- **单篇对照**：原分与观点同页；评分关联区分 explicit/inferred/unknown，条款覆盖/条件差异/潜在冲突或待核可显式保存。没有依据高分加负面词自动判矛盾。尚未实现可解释的跨稿统计、审稿人校准、修订提案试评和授权发布。

开发修正的 actor 明确为 `agent-development-correction`，状态 needs_review。它演示保存与回放，不冒充专业编辑或独立金标。概念确认、模型改进、正式条款修改是三类不同操作；本轮没有正式标准变更接口。

## 实际输入和模型探索

受控取样清单：`work/development-20261107/sources/inputs.json`，含路径与完整指纹，勿公开。12 个开发输入中 8 个接收、4 个保守拒收。接收项覆盖业务 CSV、短评、编号长评、多段长评、文字评分、小数、全空分和已知条件例；基线候选数分别为 2、1、51、101、10、4、3、13。拒收理由为不支持的 Word 特征两例、权限歧义一例、15 行模板一例。不是全库接收率或独立稿件样本统计。

真实模型采用官方 Qwen3-4B Q4_K_M、llama.cpp Vulkan 和 LangExtract 1.7.1，首次只传单个意见分区文本窗口，隐藏数值评分和表单元数据。输出、用量、结束原因、定位错误及各次 prompt/schema 指纹保留在每个 `model-artifacts/<run_id>/`。具体选型和已知失败见 [复用记录](REUSE_DECISIONS.md)。

v1/v2 发现：漏明确评价、把建议误标为否定、理由自循环、条件结构丢失、候选概念边界模板化；1743 字符评语在 8192 输出 tokens 时截断。模型引文逐字正确不等于观点完整或关系正确。后续协议复跑也作为开发实验保存，不作为独立准确率。规则在已知成对条件例上优于原模型，因此继续保留。

v3 使用 600 字窗口和较简单的引用列表协议。四例共 8 次真实本地请求，均正常结束；模型候选已导入工作区，条件例和长例分别带 11、46 个处理错误，明确标 partial。条件两支有恢复，但 CSV 仍把多观点合为句群，理由也有语义复述。agent 又将 CSV 一条合并候选拆成两个待核子观点，将条件组强度保留 unknown；历史模型与先前修正均不被覆盖。开发概念目前仅轻量整理，尚无专家定稿。
