# B内容与A位置候选分析 v1

更新：2026-11-15。本文落实用户在可复用工具讨论后确认的继续施工：A、B可变，原始B经过分析形成有证据的内容与位置候选，再由人回查、纠正、保存并直观查看。业务边界沿用[当前目标](b-attention-distribution.md)。

## 问题与结果

已交付的[输入与编辑 v1](b-attention-reuse.md)提供了跨批输入、人工建模、保存和汇总，但从原始B到观点、方面、主题、关系及A位置仍需人工填写。它是本轮基础，不能作为自动理解能力的交付证据。

本轮交付一条可实际运行的分析路径，可显式选择DeepSeek API或已安装本机模型：读取当批B全部选定评语段落，先理解B内容，再独立对照当次A；产生逐字证据支持的待核候选；通过普通界面预览、接收、回查和纠正；保存后在明细和直观位置视图查看。生成候选不等于人工确认，不以模型输出格式正确宣称语义正确。

## 可观察行为与验收

1. 输入A的部分、条目、版本和B的记录数、标识、段落、分数均可变化；允许没有A先分析B。无A显示“未导入A”，不判为清单外。
2. 分析覆盖所选记录的全部普通评语段落。合并记录不能只读首段；超出上下文或处理能力时明确说明未处理范围，不静默截断。
3. B分析先于A对照，B阶段不读取A，不把A条目变成B的唯一分类框架。可形成新主题，保留套话、礼貌、总体判断、建议和处置性表达。
4. 一个观点可含多个方面，一个方面可同时对应多个A条目。主题位置、方向、表达性质、条件、备选路径和核查状态分开保存，不用几何距离决定归属。
5. B阶段保留影响理解的否定、程度、理由、目的、条件及备选关系；不把条件分支转成无条件要求，不推造专业结论。
6. A阶段只能对经校验的B对象提出位置与理由，不能改写B原话或B分析。比较实际对象、所论属性与语境，不补造场景；有据局部或相关交集不要求B满足A全部要求。A相关、对应、清单外和待核沿用当前契约；A不是评分标准，不要求分区互斥或穷尽。
7. 每个候选绑定来源记录、段落、逐字证据和字符位置。Unicode、重复原话有明确位置时可准确引用；没有足够位置消歧时拒绝该候选，不采用首个匹配。
8. 模型候选及位置一律待核，不能自行设为人工确认或工作结论。无依据项拒绝并列出原因；部分失败保留有效草稿和未完成范围。
9. 每次运行保留版本化输入快照、请求、原始响应、模型与提示/协议指纹、调用次数、用量及错误。完成、部分、失败、零候选只说明处理结果。
10. 提供可注入的响应回放用于工程测试，同时提供实际DeepSeek API及本机模型调用。回放、模拟、API联网推理和本机推理在记录及页面中区分；记录实际模型、用量和失败，不自动切换提供方。API格式失败可在下述严格边界内追加一次修复请求，HTTP、网络或截断不重试。
11. 生成和预览不修改正式分析包。接收候选通过现有attention.apply事务，新增稳定标识，不覆盖人工对象；同run并发接收不能覆盖成功收据，重复接收幂等，源材料或A版本变化时拒绝过期导入。
12. 保存失败、重复操作、并发修订和重新打开均可解释并恢复。不能用“已生成补丁文件”代替数据库已导入的事实。
13. 普通界面允许选择范围和模型提供方、配置API凭据或本机模型、生成、预览并接收为待核；无需为每批手写JSON或编写脚本。API入口明确联网发送所选普通评语及本次A，原话本身可能含身份；原分、身份字段、本地路径及未选分区不发送。凭据不进入分析包、请求审计、网页或补丁。长操作不阻塞主线程，运行中切换目标不能把旧结果写入新包。
14. 直观视图按当批A组织参考区域，同时显示清单外、待核和未导入A。候选建议位置以待核样式显示，与正式已确认统计分开。
15. 同一方面可在多个区域出现，但记录计数去重。方向、表达和核查状态可查；A旧版本位置不能冒充当前A归属。
16. 从区域或对象可进入对应记录、原话、方面和关联理由，沿用编辑、保存与重开。视图和非图形明细使用一致筛选与分母。
17. 数量增长时先汇总再筛选、定位和钻取，不承诺无限记录或强迫全部点同时显示；能力边界和未处理范围清楚可见。
18. 用未参与实现的新A、新B验证完整路径，并分别报告工程有效性、实际语义忠实度和界面验收；不把代理演练称为用户体验或专业金标准。

## 实施决定

- 用户于2026-11-15明确要求直接接入DeepSeek API并提供凭据，本轮优先采用官方API作语义验证和普通候选路径；不做本地微调。此前本机优先是技术选择，现按新决定调整，不能再作为阻止API接入的前置。实际推理验证仍只使用合成材料，真实原件和当前真实分析包不参与测试、不自动发送或重算。API用量与估算费用分别记录，不把估算称为账单。
- API模型按用户指定采用DeepSeek-V4.1-Flash-1017，官方当前调用别名为`deepseek-flash`；本轮不使用Pro。配置注明当日官方版本映射，响应模型名原样留存；别名不冒充可永久锁定的版本端点。
- DeepSeek提供方只向显式官方HTTPS端点发送，不跟随重定向、不读取环境代理、不回退。HTTP错误、网络中断、鉴权、限流、截断及准备失败不重试。密钥支持进程环境变量和仓库外当前Windows用户DPAPI存储，调用时读取，审计只保留公开配置。API与本机提供方分开实现，不放宽原回环限制。
- 实测表明JSON模式不免除客户端格式核验。API完成响应在HTTP200、正常结束且用量已知时，若JSON语法或原schema结构不合格，最多追加一次同Flash、同输入范围和同输出上限的格式修复请求。原始响应、失败、修复请求及结果分别留审计和用量，原失败不改成通过；修复成功可继续形成待核草稿，运行仍标部分。再次不合格即停止该阶段并列明未形成候选的来源；不靠截断、丢字段或猜括号静默修补。格式合格仍须来源和语义校验。
- 本机模型作为可选配置保留。免费公开权重核验来源、许可、版本、大小及哈希，运行窗口不自动下载；运行状态和日志使用本任务独立目录，只管理可证实属于本工具的进程。本机4B和9B已有失败与对照记录保留，不因API接入改写为通过。
- 不复用旧抽取提示中排除总体判断、套话或处置表达的业务假设；复用适用的逐字校验、运行审计和保存事务。旧v3/v4运行及协议记录保留历史身份，其生产抽取入口按[改革规格](project-reform.md)退役；当前候选的显式工程回放按现行适配器核验。
- 运行审计使用版本化旁文件，正式对象遵守现有attention数据契约。保留条件等原始结构，不塞入无关字段规避校验。
- 候选预览与正式统计分别表达。人工接收只授予待核身份，不能使建议位置自动成为已确认覆盖。
- 图形是内容与证据的入口；布局不是语义证据，区域不是A的权重或评分线。

## 验证边界

补充格式验收（2026-11-17，#40）：远端模型内容 JSON 的对象字段（包括嵌套对象及转义后同名字段）重复时明确拒收，不从多个值中选择一个。符合既有修复前提时沿同一单次修复路径，原响应、首次失败、用量和修复关系保留；再次重复或用量未知时不追加修复，来源或 A 对应的未处理范围可见。这不改变本机/回放或其他输入协议，也不表示模型语义已通过。

接口测试覆盖证据、失败、过期、事务、回放、API请求与密钥隔离；真实合成API调用验证语义路径，本机配置另报实际覆盖；实际Tk操作和真实Chrome覆盖普通路径、回查与可视化。运行完整单测及scripts/check.ps1，不允许跳过替代验收。独立Spec与Standards审查固定版本，集中返修后复核，跟踪最终CI。

不在本轮增加专业复审、自动批准、A修订、评分预测、任意原始文档格式、其他云提供方或微调。输入整理和人工理解仍可使用已有入口；这不免除本轮实际分析能力与可视化的交付。
