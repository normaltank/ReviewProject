# 首轮条款审核体验：实施任务图

范围依据：[开发规格](first-framework-review.md)、Q1—Q13及用户对整体理解和自动继续项目流程的确认。常规技术选择由统筹承担；业务目标、人工最终取舍、保密和正式发布边界沿用既有决定。

主要验证入口沿用规格中已提出的完整CLI操作路径和浏览器用户操作路径。每票以外部可观察行为验证；不增加要求用户理解的私有函数测试边界。以下是本地实施与待发布工作项草稿，GitHub尚未发布。

## T1：多来源审核包与决定保存、恢复

**阻塞：无。**

从明确的小批工作区及规则资料建包，在页面查到选定观点/原分/规则出处，查看预填问题或手工整理的问题，记录保留、修改、补材料、暂缓及理由，应用后重开保留结果。预填问题明确标为手工，不冒称主动发现。

验收：去重副本、明确所用观点和规则版本、原分不改、逐字证据可查、普通与私密范围受控；旧观点可用既有入口纠正并刷新，旧包能提示材料变化；决定追加留痕、重复应用幂等、个案/通用决定分开。

实现范围：新增薄聚合包、页面及决定契约，接既有CLI；复用现有工作区与证据验证。源工作区和原始文件受保护。

## T2：主动候选发现、改法与可解释排序

**阻塞：T1已集成并验收。**

读取同一审核包，按受控候选概念及现有规则资料主动形成可审查问题；运行一个本地主要分析方案与一个规则对照，经T1页面查支持/反对材料、原分关联及其未知状态、原规则与有据改法，沿T1保存决定。

验收：模型输出先验证引用及输入绑定，失败/部分完成可见；未知不补造、相反判断不合并，原A引用不冒认草案新增内容；不同来源与权限不因聚合失去边界。排序有理由，全部候选可看，低频可能重要问题单列。模型/规则/手工来源与真实语义限制可辨。

实现范围：候选发现薄适配、既有本地模型调用复用及页面/CLI必要扩展；不新建向量库、训练平台或外部服务。

## T3：桌面试用入口、体验记录与真实小批试跑

**阻塞：T2已集成并验收。**

通过现有桌面入口选择审核包、打开页面、查证或纠正、应用决定、重开核对，并导出本次体验记录；在隔离真实小批副本跑通本地模型与规则对照，保留实际失败。

验收：用户无需手写JSON或偏移即可完成审核；下载/应用/重开状态准确，计时与待处理说明可查；当前原件与旧业务记录保持。代理演练、真实本地推理和用户本人首次体验分别标注，用户体验尚未发生时不代填结果。

实现范围：现有桌面Controller和包页面薄连接，复用体验计时记录思路；独立输出本地试跑索引，敏感材料不进仓库测试或公开工作项。

## 集成、审查与完成条件

每票独立分支/worktree；一名merger串行接收，核对同步SHA和验收后才释放后票。三个结果集成后，对固定基线至集成版本分别进行Spec与Standards只读审查，集中返修并复核。执行所需回归和浏览器验收，交付可运行入口、可查看结果、实际错误及仍未验证结论。

公开Issue、PR、推送、合并和正式标准发布按各自授权处理；它们不是本地代码实施的默认附带动作。
