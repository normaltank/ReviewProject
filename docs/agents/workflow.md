# Matt 技能工作流

2026-11-13按用户要求与OpenSource（normaltank/NewPlan）、DataBase保持同一流程。主代理作为唯一对接的统筹，直接读取并使用已安装的通用Matt技能；本项目只维护入口、协作约定和证据，不维护专属阶段技能。

## 接单与选路

先核对当前用户任务、已有Issue、已确认规格和实际工作区。读取已安装的ask-matt/SKILL.md，按任务选择并读取对应技能；沿用已有确认，不要求用户记住或逐次点技能名称。

- 业务问题尚未说清：grill-with-docs，随讨论使用domain-modeling。只澄清真正影响行为的未决项。
- 多个可分别验收的交付项或跨会话建设：to-spec → to-tickets → implement-spec。
- 范围明确且一次上下文可以完成的代码任务：implement；按tdd驱动，完成后code-review。
- 用户明确逐票推进已有任务图：按依赖逐票implement，保留整体规格与验收。
- 纯文档、导航或状态维护：writing-for-agents，由当前代理完成内容、链接、状态和范围检查；不制造应用施工任务。
- 原始缺陷或外来需求：triage；难故障先diagnosing-bugs。已有规格拆出的票不重复分流。

在当前Issue或回复说明选路和完成条件。技能中的确认先核对已有范围、粒度和测试边界，只提交剩余业务决定。需要临时子代理时按[多代理协作](multi-agent.md)实际派工；既有用户聊天不是默认施工队列。

## 跨任务建设

1. **规格。** to-spec收拢既有共识，给出可观察行为、范围、验收和验证边界。维护稿进入版本控制，父Issue发布同版本快照。
2. **任务图。** to-tickets按完整业务路径拆分，注明原生父子和阻塞关系；已有批准直接沿用。GitHub是任务状态唯一台账。
3. **实施。** implement-spec建立固定集成基线，给依赖已满足的票安排独立子代理、分支和工作树；资源冲突时隔离或串行。
4. **交接与集成。** 实施者同步最新集成提交并重验，返回提交、同步SHA和真实剩余项。merger逐份核验并串行集成；首次有效集成后建立草稿PR。已集成且验证通过可释放下游，Issue关闭另按最终交付处理。
5. **独立审查。** code-review给Standards和Spec两个只读审阅者同一比较基线、被审提交、规范及需求来源。分别保留发现和结论。
6. **统一返修。** 一名修复代理集中处理发现，经同步、验证和merger集成后由对应审阅者复核；不采纳也记录依据。
7. **交付。** 必要检查和审查对应最终提交，文档与实际行为一致，再按既有授权处理PR、合并和发布。未完成任务保持开放，清理工作树前保全所有需要的修改。

角色、隔离和交接证据沿用[多代理约定](multi-agent.md)。阶段切换按已安装ask-matt/PHASE-BOUNDARIES.md处理，保留需求到拆票的必要上下文。

## GitHub、提交与同步

- 任务状态、依赖、派工、集成和交付归GitHub Issues／PR；本地规格是维护稿，STATE或本地计划不能替代远端任务记录。
- 已确认的规格与阶段成果及时提交到对应任务分支。用户要求GitHub交付时，完成该范围检查后推送并创建或更新PR；不能只交一份本地报告，也不能把未推送提交或分支更新说成main已更新。
- 纯文档修改按已确认的提交范围交付；已有Issue则关联记录，不为一处文字修正强造任务。
- 工作区有积压时，按任务和来源拆分；只暂存本次白名单，保留其他代理的改动。不得把批量暂存、推送某个旧分支或只同步部分历史冒称积压全部交付。
- 当前分支已推送、PR待审、main已合并和已部署分别报告。最终合并沿用现有授权；技能不另授发布、敏感数据或付费调用权限。
- 已提交版本有CI时跟踪到终态；未配置CI或未运行时明确说明，不把本地检查写成CI通过。

工作项正文、固定版本和关闭规则见[Issue tracker](issue-tracker.md)。真实资料、凭据、数据库、模型和本地工作包继续留在其授权范围内。

## 验证与完成条件

代码按已确认的外部行为运行相关测试；界面和保存操作补实际验收。文档核对事实、链接、状态、跨文件一致性和差异范围，不为文案写镜像测试。

交付能追到当前任务、适用规格、实际提交、同步与集成、相应验证和两轴审查。配置、派出代理、读过技能、分析样稿和已实现产品分别说明。达到本轮验收点即收尾，额外问题进入对应Issue，不留下只存在于本地的未说明待办。

参考接入：[OpenSource工作流](https://github.com/normaltank/NewPlan/blob/main/docs/agents/workflow.md)、[DataBase工作流](https://github.com/normaltank/DataBase/blob/main/docs/agents/workflow.md)。运行以实际读取的已安装技能和用户当前决定为准，不复制技能全文。
