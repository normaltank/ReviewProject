# 多代理协作

按 [工作流](workflow.md) 分流后读取本页。主代理是唯一用户对接统筹，临时子代理在当前任务范围内执行研究、规划、实施、集成或审查；业务决定和范围变化交统筹集中处理。

## 角色与调用

角色文件位于 [`.codex/agents/`](../../.codex/agents/)。researcher 收集证据，planner 形成规格与任务图，implementer 实施指定范围，merger 集成指定成果，standards-reviewer 与 spec-reviewer 独立检查规范和需求。研究、规划与审查职责只读；这是任务约束，不宣称工具或沙箱强制只读。实施与集成仅写各自获派范围。

派工遵守 [根入口的模型默认值](../../AGENTS.md#subagent-defaults)。当前协作接口若没有自定义 `agent_type` 字段，统筹读取相应 TOML 的 `developer_instructions`，将角色职责与必要上下文写入任务消息，再通过 collaboration 工具显式设置模型、思考强度和 `fork_turns="none"` 派工。角色文件存在不等于角色已执行；模型参数已请求也不等于运行环境已确认实际模型。

使用当前任务的临时子代理；不创建用户可见的常驻聊天、不启动无限循环或后台 daemon。调用或模型不可用时记录限制及未执行环节，继续可独立推进的工作；替代方案由统筹说明，不能把缺失角色标为已完成。

## 交接字段

每次派工给出：

- 角色、任务目标、允许范围与明确的文件或 worktree 所有权。
- 仓库绝对路径、基线提交、工作分支与集成分支；多票实施包含专用 worktree。
- 需求或 Issue 指针、固定规格版本、已确认业务决定与测试边界。
- 依赖及其满足证据、验收条件、必要上下文与需读取的入口。
- 预期返回的文件、提交、验证证据，风险与阻碍的报告方式。

子代理返回实际结果、修改文件与产出提交（未提交则明示）、验证命令和结果、剩余风险及阻碍；只读角色返回带文件或需求依据的发现。多票实施另返回同步的集成 SHA、同步后验证及未提交文件。统筹核对产物和证据后更新状态。

## 写入所有权与隔离

独立任务在容量允许时并行，共享文件、数据库、端口或输出有冲突时串行或隔离。开始写入前核对 Git 根目录、分支和指定基线，保留已有修改；共享工具的默认目录不能代替明确路径。

多工单代码实施为每票提供独立分支与 worktree，并为 merger 指定独立集成分支和 worktree。实施者交接前同步最新集成版本，解决冲突并验证受影响行为。merger 接收时核对当前集成头与交接同步 SHA，确认同步 SHA 是交付提交的祖先；头已前进则退回实施者同步和重验。一次只有一个 merger 写入集成工作树，统筹与其他代理不同时写入。

单个代码结果可交一名实施代理。单次文档配置可由主代理或一名指定写入代理使用现有 checkout，其余保持只读；不为轻量维护创建虚假的多票或集成任务。

## 验收证据

merger 返回接收前与集成后 SHA、冲突处理和受影响验证。依赖只有在成果已集成且相应验收通过后才满足；Issue 关闭另按交付约定处理。

在相关 Issue 或当前交付记录关联派工角色、基线、成果、集成、审查和验证，不另造长期任务台账。统筹依据实际文件、版本和证据逐项验收，不能把配置、派工或审查数量当成实施完成。配置验证、小型委派验收与真实多工单业务验收分别报告。
