# 从原始B生成内容与位置候选

本路径从当批普通B评语生成可核对的结构化初稿，再对照当次A。A是内容参照，区域可交叠、不穷尽；图形位置不表示分数或权重。输入准备见[输入与换批](ATTENTION_INPUT.md)，保存与权限见[关注分析契约](ATTENTION_CONTRACT.md)。

## 普通操作

1. 在本机窗口准备A/B输入并建包，或打开已有关注分析包。选择“生成并核对B内容与A位置候选”，核对窗口上方固定目标。
2. 在“记录范围”多选本次B，默认选全部。每条所选记录的全部普通分区进入分析；超限和未完成范围会列出。
3. 在“本机模型设置”核对回环地址、模型名称及容量。可使用已启动的本机服务。由窗口启动时，选择含`.tools/local-llm`的已安装资源根目录，再选择父目录建立全新独立运行目录。窗口提供启动及停止自己所启动模型的按钮，运行身份与原路径一同绑定。
4. 选择“生成所选记录候选”。处理在后台运行，结果进入候选历史。生成和预览不会提交正式分析；处理完成、部分、失败、零候选及工程回放分别标明。处理完成不代表语义正确。
5. 选择“预览候选与位置”，核对选择范围、未完成项、拒收说明、原话原分、证据、限定、主题及关系。位置区域或标签可点击、键盘进入方面、原话和A对应理由。核对对象、否定、条件、处置含义以及理由是否实际对应所示A条目。
6. 候选以待核虚线图显示，与生成时冻结的保存统计分开。一个方面可出现在多个区域；记录去重，区域数不能相加。无A、清单外、位置待核分别显示。记录/材料筛选改变分母，表达筛选保留分母。
7. 在“候选历史与接收”填写修改者声明、理由，选择“显式接收为待核”。成功后新增待核对象，人工核对后再形成工作解释。重复接收同一次运行使用原收据；不同运行的候选不自动合并。
8. 选择“恢复并重开关注页”，从位置或明细进入原话与编辑区，修改后加入草稿、下载，再回本机窗口应用关注草稿补丁并恢复重开。下载仍是草稿。

生成不依赖A；A为空时表示未导入，不判清单外。每条记录独立生成主题，跨记录主题合并及关系核对仍由人工完成。个别超长记录或A超出容量时保留明确范围；可选择较小范围重新运行，不静默截断。

## 换版、失败与恢复

来源、A或保存修订变化后，旧候选保留供回查，首次接收会拒绝，须重新生成。已接收历史清楚显示接收修订，旧初稿不代表此后的人工纠正结果。运行中切换主入口不会把操作写入新包；接收前按窗口固定目标核对。

输出失败可能发生在数据库提交之后：先恢复、重开核对，重复同一次接收可安全使用原收据。窗口处理期间保持打开；窗口自己启动的模型须先停止再关闭。使用其他已启动服务不会取得其停止权。

运行目录、候选、原始模型响应及预览继承来源权限。模型文件需事先准备，窗口不下载或回退云端。本轮实际能力验证仅合成输入和本机回环模型；真实包的本机处理须由用户明确发起，不取得任何外发许可。

## CLI与运行记录

```powershell
python -m reviewproto attention-generate --workspace PATH_TO_ANALYSIS --run-id local-01 --local
python -m reviewproto attention-preview --workspace PATH_TO_ANALYSIS --run-id local-01
python -m reviewproto attention-accept --workspace PATH_TO_ANALYSIS --run-id local-01 --actor EDITOR --reason REVIEW_REASON
```

`candidate-runs/RUN_ID/run.json`保留输入快照、模式、协议与提示/适配器指纹、全部请求响应、调用用量、覆盖、拒收及候选补丁。`acceptance.json`保留确切接收补丁。工程回放使用显式`--replay`，不是实际推理或语义效果证据。完整参数以命令帮助为准，接口与失效规则见[契约](ATTENTION_CONTRACT.md)。
