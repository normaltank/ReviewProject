# 从原始B生成内容与位置候选

本路径从当批普通B评语生成可核对的结构化初稿，再对照当次A。A是内容参照，区域可交叠、不穷尽；图形位置不表示分数或权重。输入准备见[输入与换批](ATTENTION_INPUT.md)，保存与权限见[关注分析契约](ATTENTION_CONTRACT.md)。

## 普通操作

1. 在本机窗口准备A/B输入并建包，或打开已有关注分析包。选择“生成并核对B内容与A位置候选”，核对窗口上方固定目标。
2. 在“记录范围”多选本次B，默认选全部。每条所选记录的全部普通分区进入分析；超限和未完成范围会列出。
3. 在“模型设置”选择提供方与模型。普通窗口默认 DeepSeek API / `deepseek-flash`；也可切换到已安装本机4B/9B。API将联网发送所选普通评语及本次A，原话可能含身份；原分和本地路径不发送。点生成即按所选提供方处理。API密钥在遮罩输入框填写后显式保存；“检查API配置”显示已配置或缺失，生成时才读取凭据。使用本机模型时核对回环地址；由窗口启动时，选择含`.tools/local-llm`的资源根目录及全新独立运行目录。窗口只停止自己启动的实例，API选中时禁用本机启动，仍可停止本窗口已拥有的实例。
4. 选择“生成所选记录候选”。处理在后台运行，结果进入候选历史。生成和预览不会提交正式分析；处理完成、部分、失败、零候选及工程回放分别标明。处理完成不代表语义正确。
5. 选择“预览候选与位置”，核对选择范围、未完成项、拒收说明、原话原分、证据、限定、主题及关系。位置区域或标签可点击、键盘进入方面、原话和A对应理由。核对对象、否定、条件、处置含义以及理由是否实际对应所示A条目。
6. 候选以待核虚线图显示，与生成时冻结的保存统计分开。一个方面可出现在多个区域；记录去重，区域数不能相加。无A、清单外、位置待核分别显示。记录/材料筛选改变分母，表达筛选保留分母。
7. 在“候选历史与接收”填写修改者声明、理由，选择“显式接收为待核”。成功后新增待核对象，人工核对后再形成工作解释。重复接收同一次运行使用原收据；不同运行的候选不自动合并。
8. 选择“恢复并重开关注页”，从位置或明细进入原话与编辑区，修改后加入草稿、下载，再回本机窗口应用关注草稿补丁并恢复重开。下载仍是草稿。

生成不依赖A；A为空时表示未导入，不判清单外。每条记录独立生成主题，跨记录主题合并及关系核对仍由人工完成。个别超长记录或A超出容量时保留明确范围；可选择较小范围重新运行，不静默截断。

## 换版、失败与恢复

来源、A或保存修订变化后，旧候选保留供回查，首次接收会拒绝，须重新生成。已接收历史清楚显示接收修订，旧初稿不代表此后的人工纠正结果。运行中切换主入口不会把操作写入新包；接收前按窗口固定目标核对。

输出失败可能发生在数据库提交之后：先恢复、重开核对，重复同一次接收可安全使用原收据。窗口处理期间保持打开；窗口自己启动的模型须先停止再关闭。使用其他已启动服务不会取得其停止权。

启动后尚未就绪或健康检查超时时，窗口仅凭本次脚本新发出的 PID/run 身份回执保留停止能力；在“本机模型设置”停止后可重试。单独存在的旧状态文件不会授予控制权。

运行目录、候选、原始模型响应及预览继承来源权限。模型文件需事先准备，窗口不下载或回退云端。本轮实际能力验证仅使用合成输入；本机与获授权API的实测分别记录。真实包处理及任何外发须由用户明确发起，本轮合成验证不扩大材料使用授权。

## DeepSeek API配置

API只连接 `https://api.deepseek.com`，可接受同主机的 `/v1` 地址并标准化；不接受其他主机、HTTP、查询参数或用户信息。API仅支持 `deepseek-flash`，按用户指定采用4.1 Flash / 1017；官方于2026-11-15的映射为 DeepSeek-V4.1-Flash-1017。该名称是官方可调用别名，不是固定版本端点；服务返回的model原值保留在原始响应，不冒称已固定实际权重版本。Pro与其他模型明确拒绝，请改选Flash。旧抽取入口保持原行为。API与本机是显式选择，没有代理、重定向、HTTP/网络重试或失败回退；仅下述格式错误允许一次修复。

API使用 `thinking: {type: enabled}`、`reasoning_effort: high`，默认输出上限32768、超时600秒；各阶段使用同一个用户设置，不暗中提高。最大输出包含思考token，可显式调低，但可能出现空内容或截断。截断、空内容或坏JSON均保留原始响应、用量和未完成范围，不能把HTTP成功当分析完成。API上下文按1,000,000 token保守预算，仍检查完整输入、输出与余量；不使用本机采样、模板、缓存或seed参数。

密钥优先从显式 `DEEPSEEK_API_KEY` 环境变量在调用时读取，否则用当前Windows用户DPAPI解密 `%LOCALAPPDATA%\ReviewProject\credentials\deepseek.dpapi`。窗口保存的是原始DPAPI保护字节，使用应用专用entropy，不保存明文；输入框保存后清空。密钥不进入HTML、草稿补丁、运行配置、请求body或终端诊断，仅发送时加入官方HTTPS请求的Authorization header。文件存在仅表示已配置，凭据损坏、用户变更或服务拒绝仍会报错，须重新保存或核对环境变量。

仅DeepSeek API的HTTP200、正常stop且用量已知的响应，在JSON语法或原schema结构校验失败时，每个原调用可追加一次格式修复请求。它携带同一完整system/来源/schema、原不合格assistant草稿及仅修格式的说明，保持Flash、思考配置和用户输出上限。客户端不删除未知字段、不拼接括号、不改业务值来伪造通过；修复输出仍重新校验原schema及逐字/语义守卫。第二次仍坏即停止，不发第三次。HTTP、网络、鉴权、限流、截断、准备失败或未知用量不触发修复；本机与工程回放不触发API格式修复。

修复调用有独立wire请求、响应、用量、指纹及父调用ID，计入实际请求尝试数。首次调用保留失败状态与原始响应；修好后可继续形成待核候选，运行仍标部分处理，不能改为全程成功。预览和CLI明确显示格式修复次数。整条来源输出被拒收、未形成可接收候选时，列明来源及原因；这不表示模型没读取原文。需要显式重新生成或人工补录。

API的JSON模式为 `json_object`；完整业务schema写入system提示并在发送前完成请求准备。运行审计保留真正发送的body、其指纹、实际system提示及schema指纹、原始响应与原始usage（含服务返回的缓存/思考细项）。请求准备失败也留审计；不会把准备前的请求冒充wire body。`mode=remote_api`在预览中标为联网推理，工程fixture不能证明真实API语义质量。

## CLI与运行记录

```powershell
python -m reviewproto attention-generate --workspace PATH_TO_ANALYSIS --run-id local-01 --local
python -m reviewproto attention-generate --workspace PATH_TO_ANALYSIS --run-id api-01 --provider deepseek --model deepseek-flash --max-output-tokens 32768
python -m reviewproto attention-preview --workspace PATH_TO_ANALYSIS --run-id local-01
python -m reviewproto attention-accept --workspace PATH_TO_ANALYSIS --run-id local-01 --actor EDITOR --reason REVIEW_REASON
```

`candidate-runs/RUN_ID/run.json`保留输入快照、模式、协议与提示/适配器指纹、全部请求响应、调用用量、覆盖、拒收及候选补丁。`acceptance.json`保留确切接收补丁。工程回放使用显式`--replay`，不是实际推理或语义效果证据。完整参数以命令帮助为准，接口与失效规则见[契约](ATTENTION_CONTRACT.md)。

本机试验路径使用 `attention-semantic/5`：B 阶段概括关注对象并选择支持它的原文片段，再由单独的小请求分类表达作用；读法保留该片段的完整所在句，避免条件或情态被自由改写。未知与备选、否定、动作等另有逐字限定。完整类别定义和输出字段含义直接写入模型可见提示，不依赖 JSON schema 传达业务含义。流程状态专指稿件录用/接收/退修/拒稿，不泛指一般修改处理。方面与主题、关系、位置仍需逐项核对；来源绑定本身不证明这些判断正确。

关注标签与逐字证据分开：focus及范围标签可以忠实换词、概括多个片段，不要求逐字连续出现，也不以48字作为准入门槛。标签不能修复错误证据或推导精确坐标；审计分别保留原始标签和经校验的所选来源组，不声称标签就是引文。分类和A对照以所选来源组为范围权威，标签仅辅助理解，并另读本记录完整普通分区作只读语境；“据此/上述”等必要先行语境可以支持读法，但不自动成为新的关注范围。标签、表达分类和关系的语义仍须核对；例如“不要求”不能变成“不希望”，逐字证据校验本身不能证明概括忠实。

本机模型身份与采样配置共用[模型 catalog](../reviewproto/local_model_profiles.json)，由 Python 与 PowerShell 读取。本机选择、CLI `--local` / `--provider local` 和旧启动脚本仍默认 `reviewproject-qwen3-4b-q4km`。普通候选窗口的默认提供方已按授权改为DeepSeek API，不改变旧抽取器。未知手写 alias 明确拒绝，不套用受支持配置。

- 4B：`Qwen3-4B-Q4_K_M.gguf`，2,497,280,256 字节；B抽取使用512 token有界思考，表达分类使用256 token有界思考，A对照非思考。输出上限至少768，不自动提高用户上限。旧抽取入口兼容保留。
- 9B：`reviewproject-qwen35-9b-q4km`，文件 `Qwen_Qwen3.5-9B-Q4_K_M.gguf`，6,169,341,984 字节。来源 `bartowski/Qwen_Qwen3.5-9B-GGUF`，revision `182be2fd6c7bc44887d88a91cb03ff009cc9f549`，上游 `Qwen/Qwen3.5-9B`，Apache-2.0；SHA-256 `d784ce9eda1a5a7b51e8f705a9e6310844bf4f173654d115823c775fdea56d43`。所有阶段非思考，temperature 0.7、top_p 0.8、top_k 20、min_p 0、seed 42、cache_prompt false、presence_penalty 1.5，不继承4B的思考预算或阶段输出截短。每次请求保留用户配置的完整输出预算。

两配置上下文均为16384 token。运行记录保存 profile ID、catalog 指纹、模型文件身份、采样及实际请求，容量预检计入完整输入、输出和安全余量。思考轨迹仅留在本地原始审计，不进入候选解释、补丁、保存对象或普通页面。支持选择与工程验证不表示语义质量通过。

9B须由操作员预先把上述固定文件安装到资源根目录的 `.tools/local-llm`；缺失时窗口提示安装位置，脚本先检查大小再核对完整SHA-256，不下载或移动文件。显式命令示例：`scripts/start-local-model.ps1 -ResourceRoot RESOURCE_ROOT -RuntimeDir NEW_RUNTIME_DIR -ModelId reviewproject-qwen35-9b-q4km`。旧脚本不带 ModelId 继续启动4B。新状态记录 profile 与模型身份；旧无profile的4B收据仍可安全停止，错误profile不会取得停止权。

同一记录内，同一对象的同一判断及限定应只建一次，关系引用已有方面；同一引文中的不同对象或含义仍可分开；该提取要求不构成客户端自动语义合并或已证明模型不会重复的保证，须回查原话核对。

机器关系须有与类型及端点作用相符的显式连接依据；单纯邻近或同主题不能推出条件/因果。未支持的关系和明显错置的限定字段会逐项拒收，保留原提议、来源及拒收原因；不静默改写成另一种关系。保守校验不能替代语义核对，隐含但未支持的关系可由人查原话后另行补录。有据的单方面、双角色、条件与备选关系仍可保存。

有 A 时，每个方面分别请求当前每个完整 A 条目，按 B 已确定的语义范围逐行判断，并核对回传的 A/B 原文。缺省整组证据共同支持一个范围，不按标点或片段数拆行；只有 B 明确给出独立语义子范围的来源分组时才有多行，A 不新增或改写分组。仅某个范围对完整本版 A 的每一项均明确无关时，系统据这些逐项决定派生该范围清单外；任一项未定、失败或有对应，不派生该范围清单外。同方面可以同时有多个对应及其他局部清单外/未定。请求数随方面和 A 条目数增长：完整路径为所选记录数加方面数乘以（A 条目数加一），无 A 时为所选记录数加方面数。每个请求分别检查容量，超限、失败及原始响应留存，不自动重试。旧 canonical、semantic/2、semantic/3 及 semantic/4 响应保留显式工程重放兼容身份，重放使用当前适配器重新核验。

输入字符上限约束本次输入payload，固定提示与格式语法另计上下文预算。保守字节上界不足时，在同一本机服务用[模板与分词接口](https://github.com/ggml-org/llama.cpp/blob/b12110/tools/server/README.md)精确计数，保留完整输出和安全余量；预检不进行推理，失败或真超限即停止，不截断原话。`request_count`只计模型推理尝试，`capacity_request_count`另计容量预检；每次预检请求与原始响应同样留存。

提供方调用前先落盘尝试标记、开始时间与当前计数，再进入调用；`request_count`是客户端已开始的尝试，不证明服务器已收到、响应成功或计费成功，格式修复尝试也单独计入。准备失败仍为0。运行仍在执行或进程中断后，预览对已开始但未保存响应的调用明确显示结果与用量未知；旧未完成运行若缺少尝试标记/总计数则显示次数未知，不按0处理。预览只回查，不会自动继续、重试或恢复发送。

候选审计落盘遇到Windows临时访问/共享锁错误时，只在本地原子写入边界最多尝试3次，间隔50毫秒，不重试HTTP。持续失败报`E_ATTENTION_AUDIT_WRITE`，不会在发送前意图未保存时进入提供方；若已收到响应但审计落盘失败，不重发请求。请核对目录权限、占用和原运行记录，不能据本地写入错误推定网络失败或自动恢复未知请求。

A对照按原文明示的对象、所论属性和语境判断共同关注，不能从A倒补B未说的场景或行为；partial/related可保留实际局部、具体实例及较宽情境下的具体情况，不要求B复述或满足A全部要求，真正边界未明仍保留未定。此说明沿原对照调用执行，不增加核查阶段或调用数。
